## Two ways to do (almost) everything

VS Code's Explorer sidebar lets you browse, create, rename, and delete files and folders on Draco using your mouse or trackpad, much like Finder or File Explorer on your laptop. This is useful, but bioinformaticians often use the terminal instead. It is especially powerful for running programs, chaining commands together, working with many files at once, and submitting jobs to the cluster.

In this section, you will practice both approaches using the workspace and data you already have on Draco. The goal is not to choose one over the other, but to become comfortable switching between them and using whichever is most convenient for a particular task.

## 1. Where am I? What's here?

```bash
pwd   # print working directory — "where am I right now?"
ls    # list files and directories here
ls -l # list with more detail (permissions, size, date)
```

> ## Exercise 1
>
> 1. Run `cd ~/Viromics2025_workspace` then `pwd` to confirm where you are.
> 2. Run `ls`, then `ls -l`. What extra information does `-l` show?
> 3. Run `ls data/sequences`. How many files are in there?
>
> ## Solution
>
> `ls -l` shows one entry per line with permissions, ownership, file size, and last-modified date — useful for checking whether a file is empty (size `0`) or when it was last touched.

## 2. Sorting by date

Sometimes you don't want files in alphabetical order — you want to know what changed most recently (very useful once you start generating your own output files later this week).

```bash
ls -ltrh data/sequences
```

- `-l` → long format
- `-t` → sort by modification time (newest first, by default)
- `-r` → reverse the order (so with `-t`, this puts the oldest file first and the newest file last — handy for spotting your most recent output at a glance)
- `-h` → human-readable file sizes (e.g. `1.2G` instead of `1234567890`)

> ## Exercise 2
>
> 1. Run `ls -lh data/sequences` (no sorting) and note the order.
> 2. Run `ls -ltrh data/sequences`. Did the order change?
> 3. Which file is listed last? What does that tell you?
>
> ## Solution
>
> Without `-t`, files are listed alphabetically. With `-ltrh`, they're listed oldest to newest, with the most recently modified file at the bottom — a pattern you'll find yourself reaching for constantly once you're generating your own results.
>  {: .source}
{: .challenge}


## 3. Moving around: absolute vs. relative paths

An **absolute path** always starts from the root of the filesystem (`/`) and works no matter where you currently are. A **relative path** is interpreted starting from your current location.

```bash
cd /vast/groups/VEO           # absolute — works from anywhere
cd ../                        # relative — go up one directory
cd ./data/sequences           # relative — go into a subfolder from here
cd ~                          # shortcut for your home directory
cd -                          # jump back to the previous directory
```

> ## Exercise 3
>
> 1. From your home directory, move directly into `Viromics2025_workspace/data/sequences` using one command.
> 2. Use `cd ..` twice. Where are you now? Confirm with `pwd`.
> 3. Get back to `data/sequences` using a relative path from where you are now.
>
> ## Solution
>
> ```bash
> cd ~/Viromics2025_workspace/data/sequences
> pwd
> cd ../..
> pwd     # ~/Viromics2025_workspace
> cd data/sequences
> pwd     # back where you started
> ```
>  {: .source}
{: .challenge}

> ## Tip — don't retype, recall
>
> Instead of typing out a command again, press the **up arrow** to bring back your previous command, and keep pressing it to step further back through your history. The **down arrow** moves forward again. This is especially useful when you want to re-run something with a small tweak.

## 4. Looking inside a real file

```bash
cat file.txt      # print the whole file to the screen
head file.txt     # print the first 10 lines
tail file.txt     # print the last 10 lines
less file.txt     # open the file for scrolling
wc -l file.txt     # count lines in a file
```

> ## Tip — how to get out of `less`
>
> `less` takes over your terminal window to let you scroll through a file. It is **not** stuck — press **`q`** at any time to quit and return to your normal prompt. This also works for `man` pages and other tools that open this kind of scrollable viewer.

Your sequencing files are gzip-compressed, so we need to decompress them on the fly rather than opening them directly:

```bash
zcat file.fastq.gz | head -10
zcat file.fastq.gz | tail -10
zless file.fastq.gz
```

> ## Exercise 4
>
> 1. Pick any `.fastq.gz` file in `data/sequences` and print its first 10 lines with `zcat` and `head`.
> 2. Open the same file with `zless`. Scroll with the arrow keys, then quit with `q`.
> 3. Count how many lines are in the file with `zcat ... | wc -l`.
>
>  {: .source}
{: .challenge}

> ## Solution
>
> ```bash
> cd ~/Viromics2025_workspace/data/sequences
> zcat <file>.fastq.gz | head -10
> zless <file>.fastq.gz    # arrow keys to scroll, q to quit
> zcat <file>.fastq.gz | wc -l
> ```
>
> We'll dig into what these lines actually mean in the next lesson — for now, we're just practicing looking.
>  {: .source}

## 5. A file worth making: your own data manifest

`head`, `tail`, and `wc -l` are much more useful once you have a plain-text file to point them at. Let's create one that's actually useful: a sorted list of the files in your workspace.

> ## Exercise 5
>
> ```bash
> cd ~/Viromics2025_workspace
> ls -ltrh data/sequences > file_list.txt
> ```
>
> Now use what you just learned:
>
> 1. `cat file_list.txt` — see the whole thing.
> 2. `head -3 file_list.txt` — see just the first 3 lines.
> 3. `tail -3 file_list.txt` — see the last 3 lines. Which file is that, and why is it last?
> 4. `wc -l file_list.txt` — how many files do you have?
>
>  {: .source}
{: .challenge}

> ## Solution
>
> ```bash
> cat file_list.txt
> head -3 file_list.txt
> tail -3 file_list.txt   # the most recently modified file, thanks to -ltrh
> wc -l file_list.txt
> ```
>
> Check the Explorer sidebar — `file_list.txt` should now appear inside `Viromics2025_workspace` (refresh if needed). Since it's a small plain-text file, this one *is* fine to open directly by double-clicking, unlike the `.fastq.gz` files.
>  {: .source}
{: .solution}

## 6. Creating, copying, and moving things

```bash
mkdir my_folder            # create a new directory
cp file1.txt my_folder/     # copy a file into a directory
mv old_name.txt new_name.txt   # rename (or move) a file
rm file.txt                  # delete a file — careful, there is no undo!
```

> ## Exercise 6
>
> 1. In `Viromics2025_workspace`, create a folder called `day_01_terminal_practice`.
> 2. Copy `file_list.txt` into it.
> 3. Inside `day_01_terminal_practice`, rename the copy to `file_list_backup.txt`.
> 4. Now try the same kind of thing with the mouse instead: in the Explorer, right-click `file_list.txt`, copy it, paste it into `day_01_terminal_practice`, and rename the pasted copy (select it, press `F2` or use right-click → Rename) to `file_list_backup2.txt`.
> 5. Confirm both with `ls -l day_01_terminal_practice`.
>
>  {: .source}
{: .excercise}

> ## Solution
>
> ```bash
> cd ~/Viromics2025_workspace
> mkdir day_01_terminal_practice
> cp file_list.txt day_01_terminal_practice/
> cd day_01_terminal_practice
> mv file_list.txt file_list_backup.txt
> cd ..
> ls -l day_01_terminal_practice
> ```
>  {: .source}
{: .solution}

 
Both approaches land you in the same place. For a single file, the GUI is often just as fast. Once you need to repeat the same operation across dozens of samples, the terminal quickly becomes the faster, less error-prone option — exactly what we'll rely on for the rest of the course.

**Naming convention reminder:** name your working directories with a number and a short meaningful label (e.g. `10_nanoplot`, `20_chopper`) — this keeps your workspace in a sensible run-order. [See an example here](https://mgxlab.github.io/Viromics2024/draco/index.html#file-structure).
> - The VS Code Explorer does the same job with a mouse, and both views stay in sync since they're the same filesystem
